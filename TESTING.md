# Testing

## Automated (runs in CI on every push)

| Layer | What | Command |
|---|---|---|
| Unit | controller (status, Auto-Sync, Self-Heal, retries, Rollback, App of Apps, restore, deletes, decrypted-file list, plain-text secret warnings), store, API (incl. gzip), CLI (incl. `keygen`), Git, secrets, crypto, bind-mount validation | `go test -race ./...` |
| Integration | real Docker: Sync, drift, Prune vs stop of undeclared services, network/volume pruning (in use, external, bind mounts), delete with volumes, content hash for configs/secrets/bind files, absolute bind mounts, force recreate, events; remote Hosts over SSH and TLS against `docker:dind` | `go test -tags integration ./...` |
| UI | type check, build, log/ANSI parser, line diff, syntax colors (Shiki) | `cd web && npm run check && npm test && npm run build` |
| Agent connection | the WebSocket between Agent and Control Plane (M3-01): protobuf envelopes both ways, status and signals overtaking queued blob chunks, a blob cut off by a dropped connection resuming at its offset, reconnects with backoff, a dead peer found by its pings; through a real nginx with a short idle timeout: a pinged quiet connection survives many times it, one without pings is cut, a proxy restart is reconnected. Enrollment (M3-02): invites stored as hashes, single-use, refused when used, replaced or expired; a signed challenge (refused with another key, or over the bare nonce); an unapproved Agent is sent nothing until an admin approves the fingerprint it printed, a wrong fingerprint is refused; an Agent that never answers is cut off. Keys (M3-03): a replayed signature refused; a second live connection with the key locks the Host (both closed, the reason and both addresses kept) until unlocked, a dead one is replaced instead; rotation keeps the connection, the next one uses the new key, an unfinished one falls back to the old key, a new key signed by another is refused; deleting the Host closes its connection; a key file others can read is refused. Versions (M3-04): the same minor and one behind are served, two behind and newer are refused with what to upgrade, an Agent without Hello is refused, every Hello recorded with its refusal | `go test ./internal/wire ./internal/agents ./internal/store ./internal/agent`, `make test-integration` |
| Agent engines | the Agent's whole deploy path (cache, work dir, SOPS decryption, Compose, health, events, Prune, a failed Revision kept out, Remove with and without volumes) against **rootful Docker, rootless Docker and rootless Podman** | `make test-engines`; in CI on every push (job *Agent engines*) |
| End to end | throwaway OmegaCDs driven through the CLI and API against the local Docker engine: refused `./data` mounts; Live/Desired/Compose diff and plain-text secret warnings; SOPS secrets masked, never in the API, rotated; adopting hand-started stacks; the README walkthrough from GitHub; a Forgejo webhook deploying a push (skipped without a local Forgejo: `docker compose -f test/e2e/forgejo.yaml up -d`); a Sync rendered by a standalone Source Server over mutual TLS, refused without the client certificate; repository credentials saved through the Control Plane kept only by the Source Server, encrypted; `omegacd agent`: every setting in `--help`, user and systemd defaults, bad settings named; `omegacd agent rollback` lists cached Revisions and refuses an Application or Revision it doesn't have (the rollback itself, beside a running Agent with Self-Heal, in the Agent's integration tests); `OMEGACD_AGENT_WORKDIR_ALLOW` checked, an allowed root on disk warned about and refused in a container without path parity (deploying into a second root, refusing others before a file is written and moving between roots: unit and integration tests on every engine); logs (Q62): every script runs the server at debug, and those holding known secrets (SOPS values, the admin password, API tokens, a repository credential, the webhook secret) find none of them in any log; one Sync followed by its `op` from the controller into the engine; enrollment through the binary: `omegacd host add` prints the command with the invite, the Agent waits with its fingerprint, the same one `host list` shows, a wrong fingerprint is refused and the right one approves it at once, a restart needs no invite, a used invite and an unknown key are refused; `host rotate` switches the Agent's key on its live connection, a copied state dir locks the Host, `host unlock` lets it back in, `host delete` cuts it off; the Agent's version and engine recorded; no invite or signing key in any log; JSON output parses line by line; a database migration as an init service (Postgres): the app starts after it, each Sync runs it once, a failing one fails the Sync with its output and leaves the running app as it was | `make e2e`; in CI on every push (job *End to end*, with Forgejo) |
| On the supported Linux Hosts (Q61) | the whole suite (`make test-all`) on **Ubuntu 24.04** and **Debian 13**, amd64 and arm64: four Hetzner servers, native, each with its distribution's own Docker, Compose and Podman (Ubuntu: Docker 29.1, Compose 2.40, Podman 4.9; Debian: Docker 26.1, Compose 2.26, Podman 5.4). All four run the same tests on the same engines: rootful and rootless Docker, rootless Podman in a container, and the server's own rootless Podman as the test's user. Files on Linux's own disk with real owners and modes | `make test-linux` (Hetzner servers from the separate omegacd-testinfra project: `make up` before, `make down` after); CI: Go, Agent engines and End to end on amd64 and arm64 runners |
| Security | secret scan of the full Git history | gitleaks (CI) |
